# 数学、模型与机制

使用提示：本文件提供可选讲解思路，按目标、已有知识和当前反馈取舍。步骤顺序、练习及输出形式可以改变；事实准确与项目授权边界仍需遵守。

## 先决定深度

| 目标 | 需要讲到哪里 |
| --- | --- |
| 正确使用工具 | 输入输出、核心机制、参数作用、适用条件 |
| 自己实现一个运算 | 符号、维度、数值例子、关键推导与代码对应 |
| 修改方法或解释其依据 | 定义与假设、推导理由、近似、边界与替代方法 |

不能把“完整推导 Transformer”设为使用蛋白模型的通用先修要求；也不能以调用 API 为由省略影响结果解释的原理。

专业名称与公式是理解和检索的入口。重要方法、运算或量首次重点讲解时给出规范名称及通行英文，并展示与当前问题有关的公式。解释符号和成立条件，用数值或图示建立直觉后，逐渐进入推导；不要用“某种评分”“一组数”长期替代正式定义，也不要求为点名概念一次展开全部理论。

## 解释链

下面是一种可选路径：从问题出发解释为什么需要这个量；定义符号及其对象、维度、单位和取值范围；用小数值例子计算；连接一般公式；必要时逐步推导；最后对应到实现及检查。

若用户明确要推导，可先给定义和待证目标，再推导。每步说明使用了什么定义或运算法则；不把经验选择写成数学必然，也不把直觉类比当证明。

发现先修缺口时，只补当前所需的小片段。例如先说明向量是一组数、各轴含义，再讲矩阵形状；反复出现的基础缺口才安排独立小课。

## 最小示范：掩码平均池化（masked mean pooling）

教学例子：有效位置向量为 (2,4)、(4,8)，补齐位置为 (0,0)。两个有效位置平均为 (3,6)，若错误地除以三个位置则变为 (2,4)。先让学习者看出分母代表什么，再给公式：

`z = sum_i(m_i * h_i) / sum_i(m_i)`，其中 m_i 为是否参与汇总的 0/1 标记，分母必须大于零。

讲清求和轴、广播和输出维度，再写实现。这里演示一个运算，不宣称平均池化适用于所有模型和任务；实际有效位置、特殊 token 和表示层需核对模型文档。

## 主动引导

- 改变一个参数时，哪项会改变、哪项应保持不变？
- 输入单位、序列长度或 batch 变化，公式仍成立吗？
- 公式优化的量与实验真正关心的性质相同吗？
- 哪些结论是数学推导，哪些需要数据验证？

让学习者补一个关键步骤或做一次小计算；不要把大量机械推导作为唯一验收。对模型输出尤其区分表示、概率、评分、实验量和临床解释。
