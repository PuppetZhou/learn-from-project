# 调试、验证与工程优化

使用提示：本文件提供可选讲解思路，按目标、已有知识和当前反馈取舍。步骤顺序、练习及输出形式可以改变；事实准确与项目授权边界仍需遵守。

## 调试的教学主线

先区分程序报错、程序成功但结果错误、结果正确但资源成本过高。收集实际命令、输入范围、版本、日志和预期，不依靠旧状态猜测当前运行。

依次展示：预期与实际 → 最小失败输入 → 可能原因 → 能区分原因的观察 → 单项修改 → 复核。每个实验说明“这个结果支持或排除了什么”，而不只是给出修复命令。

优先读最早相关异常及其上下文；最后的进程池错误可能只是上游故障的传播。区分存储/解压、格式解析、数据关联、科学规则和资源不足。技术困难不能通过静默删除记录或改变规则绕过。

## 结果验证

用人工可判断的小例子或独立关系检查：输入数如何分解、字段是否对应、引用是否仍存在、边界如何处理。不要仅把生产实现复制到测试里。

合成例子检验指定逻辑，不证明真实来源覆盖完整；局部真实运行不证明全量成功。教学时明确验证覆盖了什么。

## 优化与设计改进

| 观察 | 可讨论的改进 | 必须保留的边界 |
| --- | --- | --- |
| 同一文件被反复读取 | 合并查询、批量读取 | 不遗漏原本需要的字段或记录 |
| 相同输入重复计算 | 缓存、去重请求 | 键包含决定结果的版本/参数，保留来源支持关系 |
| 全部记录一次放入内存 | 流式读取、分批写出 | 跨批次重复、排序、汇总语义不能改变 |
| 独立任务计算耗时长 | 受控并行 | 先判断 CPU、磁盘或网络瓶颈及总内存 |
| 长任务失败需从头跑 | 阶段或分片检查点 | 验证依赖与完成状态，不能只看文件存在 |
| 一个函数承担多种职责 | 分离规则计算与 I/O | 不为简短函数强行抽象；展示可读性收益 |

没有测量时将性能判断标为待验证假设。先讨论最可能有价值的一项，说明额外复杂度与维护成本。局部提速不能直接外推全量。

## 引导问题

“哪条证据说明错误发生在解析之前？”“如果记录数相同，结果是否一定相同？”“哪些输入变化会使缓存失效？”“如何知道增加进程有帮助？”

可以从已完成且可追溯的故障报告教学；不要为了演示故障破坏真实文件。结束时让学习者提出下一条诊断命令或验证例子，并解释目的。
