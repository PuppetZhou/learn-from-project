# 拆解已有项目仓库

使用提示：本文件提供可选讲解思路，按目标、已有知识和当前反馈取舍。步骤顺序、练习及输出形式可以改变；事实准确与项目授权边界仍需遵守。

目标：让学习者理解任务如何被代码分工完成，并能找到修改/检查位置。不要从遍历所有文件或逐行 imports 开始。

## 阅读和讲解次序

1. 核对项目说明和现行规则，选一个用户关心的用途。说明最终输入输出；对象/格式不清时先补背景。
2. 找到对应命令入口、参数和直接调用路径。只读当前目标所需文件，不把目录清单当调用图。
3. 选一条记录或一个小任务贯穿执行。区分数据流（数据传给谁）、调用关系（谁执行谁）、控制状态（何时跳过/失败/恢复）。
4. 用小表列出关键阶段：责任、输入输出、实际实现位置、依赖。函数被调用顺序与文件排列顺序可能无关。
5. 解释拆分理由：隔离科学规则与 I/O、共享参考、昂贵工具、独立恢复或可单独验证。若未找到设计依据，明确这是从代码推断，不冒充作者意图。
6. 对照当前规则审视实现；有不一致时说明，不为了教学把错误合理化。
7. 选择一个需求变化，展示哪些模块要改、哪些结果失效。最后再讨论一个有依据的优化机会及代价。

## 三种深度

- 导览：认识入口、核心阶段与结果，可在少数段落结束。
- 追踪：跟随单条输入，展开关键函数、状态和引用。
- 设计复盘：比较当前拆分与更简单的方案，分析修改成本、验证和性能。

按照用户需求选择，不默认全部完成。讲解项目不授权修改项目。

参考 [原创仓库样本](../assets/worked-examples/repository.md)。实际输出必须链接核对过的真实文件，不把样本文件名当真实仓库存在。
