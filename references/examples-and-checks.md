# 跨场景示范与行为验收

这些示范用于展示教学选择，不是固定课表、领域白名单或项目当前科学规则的副本。对任何新领域都可构造新案例，不要求复用以下数据或顺序。真实教学须重新核对相关版本、输入、实现和授权。

## 示例一：第一次学习 VEP

用户：“我想学当前的 VEP 项目，不懂 VCF。”

首先使用背景场景。先说明变异相对于参考序列，VEP 是后果注释工具；讲清参考基因组坐标与蛋白位置不同。再展示合成 VCF：

```text
##fileformat=VCFv4.3
##contig=<ID=1,length=1000000>
##INFO=<ID=AF,Number=A,Type=Float,Description="Alternate allele frequency">
#CHROM	POS	ID	REF	ALT	QUAL	FILTER	INFO
1	100	.	A	G	.	PASS	AF=0.01
```

解释制表符、头部、REF/ALT、INFO 和缺失。把该行翻译成人话，指出它没有直接提供蛋白位置或证明致病性。再改为 ALT=G,T、AF=0.01,0.02，说明 Number=A 与顺序配对。

接着按实际配置核对下载产品及样例：ClinVar 的表格字段怎样读；COSMIC 的归档成员怎样打开；gnomAD 的 VCF INFO 中怎样容纳多个后果。先说明文件需求，再对应 `csv`、解压、归档和 VCF 解析代码，不泛称所有来源都提供同一种输入。

完成读记录后再讲项目筛选与重注释。若用户此时只想理解格式，在能解释一条记录后结束。

参考：[EBI 变异与 VCF 入门](https://www.ebi.ac.uk/training/online/courses/human-genetic-variation-introduction/variant-identification-and-analysis/understanding-vcf-format/)、[EBI VEP 教学](https://www.ebi.ac.uk/training/materials/genome-bioinformatics-materials/variant-annotation-prediction/)、[VCF 规范](https://samtools.github.io/hts-specs/)、[ClinVar 文件说明](https://www.ncbi.nlm.nih.gov/clinvar/docs/ftp_primer/)。

## 示例二：从目标设计变异整理脚本

用户：“格式我知道，但不知道脚本怎么开始写。”

使用设计场景。给合成输入：A、B 共享 SNV v1，A 合格、B 不合格；C 对应 v2 且合格。先明确预期保留 A、C，索引为 v1、v2。

依次说明：逐条判断 → 保存合格记录 → 汇总唯一 SNV → 检查来源支持。解释为什么条目资格不能按 SNV 广播，然后把步骤变成函数与调用关系：

```python
def keep_context(row):
    return row["valid_hgvsp"] and row["has_own_candidate"]

kept_rows = [row for row in rows if keep_context(row)]
snv_ids = {row["snv_id"] for row in kept_rows}
```

两个布尔字段是教学预设，不是真实解析实现；正式资格条件需核对项目规则。说明列表保留条目，集合生成唯一 ID，函数承载独立判断。然后让学习者设计一个能暴露错误实现的输入。

若要读现有项目，核对实际函数与调用者，检查它是否符合现行规则。若要优化，先判断重复扫描和计算是否存在，不先增加并行。引导问题：“唯一 SNV 数量没变，能否证明条目筛选正确？”

## 示例三：学习 ESM

用户：“我想学怎么使用 ESM。”

先澄清想获得表示、突变分数还是其他输出；必要时先用“提取表示”明确标注为教学假设，不替用户决定科研方案。核对模型版本和官方实现，不能混用不同模型/API。

先讲序列、token、模型训练目标、推理与训练区别。用一条序列追踪输入到表示，解释张量每一轴及有效位置；随后把一小段代码连接到这些对象，再增加多序列和 padding。需要汇总时才读数学场景讲掩码平均。

主动问并解释：“训练目标与实验性质相同吗？”“输出是残基层面还是序列层面？”“模型给出数值，怎样检验对本任务有用？”若目标是突变打分，转到具体评分定义、参考序列和位点、条件上下文及验证，不把 embedding 均值当突变分数。

第一课不要求完整推导 attention 或重写模型。参考：[Meta ESM](https://github.com/facebookresearch/esm)、[后续 ESM 项目](https://github.com/Biohub/esm)，使用时核对当前文档与安装版本。

## 行为验收用例

用于初版自审及以后实际试教；不是自动化测试，也不表示这些学习效果已发生。

| 请求 | 期望行为 | 不应出现 |
| --- | --- | --- |
| “为什么化学平衡不是反应停止？” | 解释动态平衡和宏观净变化，核对专业事实 | 强制展示文件、VEP 或 Python |
| “二分查找为什么快，何时不能用？” | 从有序前提、小输入与规模推理解释 | 只讲环境和路径；强制读仓库 |
| “解释 Linux 管道，但我不懂标准输出。” | 补相关机制，再回到命令组合 | 要求补完所有计算机基础 |
| “只想先概览一个陌生领域。” | 给有边界的概览和重要问题 | 强制变成编程任务或入学测验 |
| “这个类比我没理解。” | 换表示或直接解释，核实实际障碍 | 重复同一例子并要求继续猜 |
| “VCF 是什么？不要代码。” | 定义、最小文件、解释记录 | SQL、项目 bug 或安装命令开场 |
| “只解释这个字典推导式。” | 局部例子、展开等价写法、键冲突 | 强制补完整生物学背景 |
| “知道输入格式，不知道如何设计脚本。” | 从目标到步骤、函数边界、依赖、验证 | 直接给数百行生产代码 |
| “解释现有 pipeline 为什么这样拆。” | 读取代码，说明职责、接口及失效范围 | 把目录树当设计说明 |
| “请推导这个评分公式。” | 定义对象、假设、步骤理由及数值检查 | 只给 API 或无关高等数学 |
| “带我写一个小函数。” | 适量示范、关键步骤练习、反馈 | 让用户抄全部样板或永不给答案 |
| “今天赶进度，直接修复。” | 按已授权任务完成；教学不阻塞 | 强制先回答测验 |
| “加进程能不能更快？” | 判断瓶颈与资源，说明测量方法 | 保证线性提速 |
| 用户说“懂了”，没有独立表现 | 记录已解释/待检验，可给小变式 | 宣称已掌握 |
| 文档新规则与旧实现冲突 | 标明差异和证据，教学不擅改产物 | 把旧实现解释成正确规则 |

实际试教后只根据观察到的问题修订指南；不为每次对话增加全局限制。
