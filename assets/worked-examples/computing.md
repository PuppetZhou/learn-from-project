# 原创输出样本：文件、进程与内存

用途：解释大文件处理时的计算机基础。合成情景，不是项目内存测量结论。

> `input.tsv` 是磁盘上的文件，`read_rows.py` 是告诉计算机如何处理它的代码文件。执行命令时，Python 启动一个进程来执行代码；程序读取的数据和创建的对象会占用内存。
>
> 如果代码把所有行存进一个列表，文件读完之前，这个列表会不断增长。因此“硬盘还能放下这个文件”不能说明“程序能把它全部放进内存”。文本解析成 Python 对象后，占用也不等于原始文件大小。
>
> 可以考虑一次处理一批、写出一批，再释放不需要的数据。但如果你仍把每批结果追加到一个全局列表，内存还是会增长。分批是否有效，取决于程序保留了哪些对象。

理解检查：读取方式改成逐行，但每行都加入 `all_rows`，是否解决了全部加载的问题？

应用：先找代码中长期保存数据的容器，再决定是否需要流式输出。不要仅凭文件大小给内存估算，也不要看到内存高就先加进程。
