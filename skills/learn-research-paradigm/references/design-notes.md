# 设计依据

维护参考，非授课必读。以下资料于 2026-11-21 查阅；将其原则用于 agent 教学是本 skill 的设计选择，尚不代表经过学习效果评估。

- [Keshav：How to Read a Paper（2007）](https://cs.uwaterloo.ca/~brecht/courses/854-http-video-2012/readings/keshav-paper-reading.pdf)：先概览、再理解内容、按需要深入。用于选材与阅读深度，不要求每篇都完成固定轮次；这是作者提出的阅读经验方法。
- [Carnegie Mellon：Course Content & Schedule](https://www.cmu.edu/teaching/designteach/design/contentschedule.html)：围绕学习目标取舍内容，让新知识与前面内容相接，避免覆盖过多挤占应用机会。用于控制讲授范围与保持教学主线，允许不同授课顺序。
- [4C/ID：The model](https://www.4cid.org/about/)：以完整学习任务为骨架，连接理解领域所需的理论与执行时所需的程序性信息。用于整体路线、贯穿案例与按需补充操作，而非把专业教学模型完整变成每轮回答的固定模板。

入口独立保留角色、语言、检索责任与成功标准；参考分开处理学习讨论、选材、流程组织和材料解读。这样 agent 不读参考也能开展学习讨论或教学，有具体需要才加载细节。暂不加入脚本、案例库或共享必读文件；真实使用出现稳定缺口时再增补。

前期讨论依据用户反馈加入：已有知识帮助建立初步框架，检索核对并补充，再提供有材料支持的可选路线。只追问影响选择的信息，明确目标时直接教学。区分学习路线与研究方法分支，避免把一种教学顺序误当成唯一研究范式。

后续从实际回答观察：能否先呈现范式再进入步骤；能否用资料解释选择理由而非堆书单；能否区别通用做法与工具实现；能否在追问后接回主线。格式检查只验证 skill 可加载，教学质量需要真实学习反馈。

语言优化采用入口明确守则与可选案例相结合的方式：默认低门槛解释，按学习目标主动深入，避免术语堆叠和专家跳步。核对的官方指南与教学来源见 [表达与分层讲解](explanation.md)。两个教学 skill 各自保留完整指引，单独安装也能使用。
