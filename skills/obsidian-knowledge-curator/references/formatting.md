# 格式整理

## 标题与编号

整篇学习笔记默认使用一个文档标题和两层编号：

```markdown
# 笔记标题

## 1. 第一部分

### 1.1 第一个主题

### 1.2 第二个主题

## 2. 第二部分
```

一级标题不编号；二级用 `1.`、`2.`；三级用 `1.1`、`1.2`、`2.1`，数字后留空格。细节使用段落、加粗引导词或列表。短笔记按需使用其中的层级，用户指定的风格优先。

统一整篇同级标题的编号，替换旧编号，检查连续性；子级在新父级下从 1 开始。原有更深标题可合并为段落或加粗引导词，保留内容的归属与含义。

## 段落与强调

解释和推理用段落，并列要点用列表，执行顺序用有序列表，多对象按共同维度比较时用表格。段落之间留空行；代码、公式、表格前后留空行。

标题前后的正文负责交代关系，不把所有解释拆成列表。加粗突出少量关键词或短引导语，整段强调和频繁装饰会削弱层次。

## 公式、代码与链接

格式任务保留公式和代码原意，代码块标明语言，数学使用 `$...$` 或 `$$...$$`。代码、数学块、YAML 和引用中的示例与正文分别处理。

普通 Markdown 默认使用 `[说明](相对路径.md)` 和 `![说明](相对路径)`，相关文件可随目录一起移动。沿用当前项目的链接规则；文件名有空格时使用适合目标渲染器的链接编码。改标题或路径时检查相应链接。

数学、表格和标题锚点的支持取决于渲染器。目标支持数学时使用上述公式写法，纯文本阅读仍应能由符号解释理解内容；未明确环境时优先常见 Markdown 写法，不依赖插件语法。

已有 Obsidian 双链、块引用等内容时按 [Obsidian 适配](obsidian.md) 处理。转换为通用 Markdown 是单独的转换任务，不能只替换括号而遗漏目标和附件。
