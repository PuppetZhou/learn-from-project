# 格式整理

## 标题与编号

对整篇学习笔记做格式统一时，默认只用“标题 + 两层编号”；用户指定其他风格时以其要求为准：

```markdown
# 笔记标题

## 1. 第一部分

### 1.1 第一部分的主题

### 1.2 第一部分的另一个主题

## 2. 第二部分

### 2.1 第二部分的主题
```

- 一级标题不编号；二级用 `1.`、`2.`；三级用 `1.1`、`1.2`、`2.1`。数字后留一个空格。默认不再添加 `1.1.1` 等更深层标题；细节根据内容使用段落、加粗引导词或列表表达。
- 逐级检查整篇：同级标题不混用中文数字、阿拉伯数字和无编号；数字连续，子级在新父级下从 1 开始。替换旧编号，不在原编号前再加一层。
- 原有深层标题需要整理时，保持其内容和语义：视上下文并入段落或转为加粗引导词；不要因为压低层级而删除定义、结论或例子。代码块、YAML、数学块和引用中的示例不作为正文标题。
- Obsidian 标题链接依赖标题文字：加编号也会改变锚点。先检查文内及必要的库内入链，包括 `[[笔记#标题]]`、`[[#标题]]` 和 Markdown 标题链接；更新授权范围内受影响的链接。无法安全处理范围外链接时保留目标并说明。

## 段落与 Obsidian 语法

- 保留必要的导读和过渡句：父标题与一组子标题之间如需说明其关系，使用简短正文引出，不要直接跳到列表。段落、列表和表格各有用途，不把所有内容压成碎片。
- 保留 `[[双链]]`、`![[附件]]`、标题和块链接、`^块ID`、callout、引用、任务状态及已有 YAML；不将 wikilink 批量改成普通链接。表格中的双链别名使用 `[[笔记\|显示名]]`。
- 原有公式、代码、命令、路径及代码块缩进保持原样；新增公式使用 `$...$` 或 `$$...$$`，新增代码块标明语言。格式整理不改变技术含义。
- 执行 `check_headings.py` 检查完整笔记；它核对默认两层编号，不验证链接解析或用户自定义风格。再人工检查层次、承接句和锚点。
