# Markdown 笔记制作与整理

把材料整理成日后容易阅读、查找和应用的 Markdown 笔记。围绕当前问题留下完整主线、关键概念与必要细节；篇幅以能理解和复用为准，避免扩写成面面俱到的教材。

## 核心写作要求

标题让读者看出结构，正文用自然、准确的短段落讲清关系。保留必要的导读与承接句；并列内容用列表，比较用表格。默认使用一个文档标题和两层编号：`## 1.`、`### 1.1`，细节放在正文中；短笔记可少用层级。

按材料选择结构和深度。概念笔记讲清含义与区别，方法笔记保留关键过程和条件，全流程笔记先让读者看清各阶段的目的与衔接。公式、代码、案例和复习问题各自有用时再加入，不凑固定栏目。

补充以弥合当前理解缺口为准，精简优先处理重复与空话。保留关键条件、推理联系和来源，让笔记脱离原对话仍能读懂。内容完整即可收束，相邻主题可用简短说明和链接连接。

## 文件与交付

优先使用用户指定的文件、目录和环境。普通目录直接维护 `.md`；服务器通过已有终端、挂载或连接访问。连接信息不足时说明所缺信息，不把服务器请求转写到本机默认库。目标为 Obsidian 时再采用对应适配。

已明确保存位置时写入文件；仅要求正文时直接提供 Markdown。修改前读原文，保留公式、代码、来源和已有引用的含义，重要科学补充或修正核实依据。改标题或文件名时处理受影响链接；写回保留可恢复版本，同步目录留意并发改动。

完成后检查主线、层级和引用，简要报告实际修改。笔记正文保持知识内容本身，不附编辑过程报告。
