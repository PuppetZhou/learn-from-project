# 讲解样本：筛选记录与提取 ID

以下是可改写的课堂片段，输入为合成数据。

我们想做两件事：先留下符合条件的记录，再看看这些记录涉及哪些不同的 ID。这两个问题很接近，但需要的结果不一样。先看三条记录：

```python
rows = [
    {"id": "v1", "keep": True},
    {"id": "v1", "keep": False},
    {"id": "v2", "keep": True},
]
```

`keep` 在这个例子里已经给出了是否保留的判断。前两条虽然都有 `v1`，却是两条不同的记录：第一条应保留，第二条不应保留。因此，我们得先逐条检查，而不能只看 ID。

```python
kept = []
for row in rows:
    if row["keep"]:
        kept.append(row)
```

循环每次拿出一条记录。第一条的 `keep` 是 `True`，所以被放进 `kept`；第二条是 `False`，跳过；第三条是 `True`，也被放进去。这样 `kept` 中留下的是第一条和第三条完整记录。

如果你见到下面这行，它做的是同一件事，只是用了列表推导式（list comprehension），把循环和条件写在一起：

```python
kept = [row for row in rows if row["keep"]]
```

现在才轮到第二个问题：留下的记录涉及哪些 ID？这时我们只取 `id`，用集合（set）保存不同的值。集合会合并重复值，所以适合回答“有哪些不同的 ID”；需要保留每条记录时，刚才的列表才有用。

```python
ids = {row["id"] for row in kept}
```

这里集合包含 `v1` 和 `v2`，不依赖它们的排列顺序。假如以后有两条合格记录都属于 `v1`，列表仍会保留两条记录，集合则只保留一个 `v1`。

还要注意一个容易混淆的地方：如果用这个 ID 集合回头查原始 `rows`，把所有 ID 匹配的记录都取出来，第二条也会回来。它的 ID 确实在集合里，但它自己并不符合保留条件。这就是为什么“某个 ID 入选”和“这个 ID 下的每条记录都合格”是不同的判断。
