# 讲解样本：一个输入怎样走过项目

以下项目和文件名为虚构示范，展示讲解方式。

这个项目做的事情可以先理解为：从表格中读出记录，留下符合条件的部分，再把结果保存下来。我们跟着一条记录走一遍，就能知道各部分为什么存在。

假设你在命令里给了一个 TSV 文件路径。程序首先需要知道读哪个文件，这由入口 `main.py` 接收。此时程序拿到的还只是路径，并没有读懂表格内容。

接下来，读取函数把文件里的文字转换成代码能处理的记录。比如一行里的 ID 和是否保留标记，会变成一条可以按字段取值的数据。这部分放在示例中的 `io.py`，负责解决“文件里的内容怎样进入程序”。

拿到记录以后，程序才判断它是否符合条件。这部分在 `rules.py`。把读取和判断分开有一个实际好处：我们想研究筛选条件时，可以直接给判断函数几条小记录，不必每次都准备一整个文件。文件怎么存、条件怎么判，是两个可以分别理解的问题。

判断完成后，`build.py` 把保留的记录组织成结果，交给写出函数保存。于是最初给程序的文件路径，经过读取、判断和组织，最终变成了一份筛选后的表格。

现在再看这些文件名，它们就有了对应的作用。小项目也可以把这些函数放在同一个脚本里；理解职责怎样连接，比记住拆成几个文件更重要。以后若只是文件格式变了，我们先看读取部分；如果保留条件变了，就先看判断部分及受它影响的结果。
