# 表达与分层讲解

需要改进讲法时选读，不是每次授课的必读材料。入口中的守则已足够指导日常回答；下面的例子用于说明表达差异，不规定所有主题的顺序或格式。

## 把易懂和深入接起来

用户提供的 ELI5 提示词强调默认易懂、按需深入。这里将它落实为：降低理解门槛，保持成人交流语气，先给直觉，再讲到当前目标需要的机制与条件。“容易读”不等于省略推导，也不等于每个概念都要编一个生活比喻。

根据已有基础选择层次。只想快速上手时，重点解释操作目的、输入输出和判断依据；想学原理时，继续展开假设、关系与推导。明确要求公式或实现时直接提供，并保持符号与具体对象的对应。用户没有追问，也应完成已约定的教学目标。

## 用一个小例子连接表达

只有“通过梯度下降优化目标函数”时，初学者可能不知道调整什么，也不知道为什么能变好。可以这样展开：

> 我们想把一个可调整的数 θ 移到 3 附近。用 L=(θ−3)² 衡量它离目标有多远：θ=1 时，L=4。L 是这次要减小的误差，也叫损失。
>
> 在 θ=1 处，损失对 θ 的导数是 −4。负号表示：在当前位置附近，θ 稍微增大，损失会减小。梯度下降沿导数相反的方向调整 θ；若步长取 0.1，这次更新就是 θ←1−0.1×(−4)=1.4。新的损失是 2.56，确实比 4 小。步长决定一次走多远；过大的步长可能跨过合适的位置，所以并非任意更新都能让损失下降。

这个例子把对象、符号、局部变化和结果接在一起。数学基础不足时可先用数值比较解释方向，再介绍导数；已有基础时可直接讨论更新式与收敛条件。不要把同一段话换几个近义词当作降低难度。

## 没听懂时怎样调整

先定位具体缺口：术语不明就解释对象和用途；步骤不明就展示一个中间状态；理由不明就比较采用与不采用该步骤的结果；过于抽象就换一个可计算或可观察的例子。理解后再连接正式表达，不停留在类比中。

使用类比时挑选对应关系清楚的一个，指出会影响结论的差异。若类比引入的新概念更多，直接用原领域的小例子往往更合适。对熟悉概念不反复降级解释，也不用“显然”“你只需要”掩盖关键前提。

## 设计来源

2026-11-21 核对以下一手资料，提炼为本 skill 的表达选择；尚未据此验证实际教学效果。

- [OpenAI：GPT-6 Astra 写作提示](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md#prompting-best-practices)：明确要求平实语言、具体例子、每段一个意思，并按读者背景调整技术细节。用于入口语言守则，不照搬全部模型提示。
- [OpenAI：Prompt engineering best practices](https://help.openai.com/en/articles/6654000-best-practices-for-prompt-engineering-with-the-openai-api)：具体描述期望行为，提供有用示例，说明应该怎样做。用于将“像好老师”“说人话”转为可执行指引。
- [OpenAI：Study mode 的分层解释](https://help.openai.com/en/articles/11780217-using-study-mode-in-chatgpt)：从简单解释开始，随学习准备程度增加细节。借鉴这一产品设计，不要求每段都用苏格拉底式提问。
- [The Carpentries：Expertise and Instruction](https://carpentries.github.io/instructor-training/04-expertise.html)：专家可能跳过初学者需要的中间连接，或无意切换术语与表示。用于补齐关键步骤、稳定称呼。
- [The Carpentries：Memory and Cognitive Load](https://carpentries.github.io/instructor-training/05-memory.html)：限制同时引入的新概念，建立知识关系并提供适当支持。用于按阶段控制信息量，不设机械的字数或术语数量上限。
