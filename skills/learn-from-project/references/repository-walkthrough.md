# 把项目讲成各部分协作的故事

选择用户关心的一次使用过程，读说明、入口和直接相关实现。先讲这个项目帮助解决什么问题，再让一个具体输入贯穿解释。

例如可以从“你提供一条序列，最终希望得到什么”讲起，依次解释哪部分读取它、哪部分转换它、哪部分计算、结果如何被使用。每到一处，说明它为什么存在、如何接上前一步；函数名和路径放在对应解释旁边。

先让用户看懂整条主线，再放大当前最关键或最困惑的一段。目录树只负责定位，不能替代执行过程。必要时用一张小流程图表现关系。

“为何这样拆分”属于后续解释：依据代码说明哪些职责不同、怎样协作；设计动机若只是推测，说明推测依据。用户关心扩展或性能时再比较方案，不把项目导览自动变成代码审查和重构计划。

结束时用贯穿案例接回最初的问题，使用户理解输入为何成为这个结果，而不仅记住模块名称。
