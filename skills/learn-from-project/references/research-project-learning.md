# 全局视角下的项目教学

适用于系统学习、全过程和完整 demo。先建立完整路线，再在路线中深入；局部知识问答不必展开整套课程。

## 先说明目的与全程

从最终希望理解或完成的事情倒推关键阶段。把“先做什么、随后做什么、为什么这样衔接”讲给用户听。每个阶段至少能看出它解决的问题、产生的结果，以及后续如何使用这个结果。可用短文、简表或流程图，重点是说明关系。

区分完整目标与本轮重点：先让用户知道全程，再说明现在从哪里开始。模型自主选择阶段数量和粒度；不要把用户的“全过程”默默缩成当前最熟悉的一小段，也不要只列一份课表就结束。

## 用简化的完整任务承载学习

选择能覆盖目标主线、规模适合学习的 demo。说明它从什么开始、到什么结果结束，以及哪些生产规模或高级内容被简化。复杂度可以降低，关键阶段间的连接要保留。

如果用户要可运行的完整 demo，在条件允许时给出或实现贯通关键阶段的最小版本，并解释如何运行和读结果。若选择互动式分阶段实现，明确这是完整 demo 的当前部分，持续向终点推进。大段代码的存在不等于全过程已被讲清，第一步跑通也不等于 demo 完成。

## 从每一步的理由走到代码

进入某阶段时，接住上一阶段的结果，解释现在需要解决什么、为何要采取这一方法，再将关键思想对应到代码中的对象和操作。运行或演算后解释结果如何支持下一步。

先讲影响理解的机制，再按需要放大语法、数学或工具细节。暂时用不到的分支可以简述其作用后继续；重要先修缺口则及时补足。理解与实践交替推进，避免把整套理论与整套代码分成互不相接的两大块。

## 互动中保持方向

用户提出疑问时定位卡点，选择解释、对比、示范或小练习。问题解决后用自然的承接回到当前阶段。出现新问题时判断它是否影响继续学习：影响就补，不影响就说明它与主线的关系后适时再讲。

在阶段转换或跨轮继续时简短定位：已经理解或完成什么，现在处理什么，接下来为什么需要那一步。无需每条消息重印整张路线，也不要求每一步答题通过。依据实际回应调整帮助，不能把用户没提问当作已经掌握。

完整过程讲完后，帮助用户把各阶段重新串起来，解释一个条件变化会影响哪里。需要持续保存学习记录时，记目标、当前位置、实际困惑与下一步即可。
