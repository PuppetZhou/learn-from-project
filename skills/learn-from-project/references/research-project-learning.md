# 把研究项目组织成连续课程

先用一小段说明研究问题、数据和方法如何相连，让学习者知道为什么值得学。再给简短路线，并实际开始讲当前主题，避免首轮只有课表。

## 随着知识依赖推进

对于机器学习项目，一条可能的主线是：想预测什么 → 数据怎样表达这个问题 → 用什么办法建立预测 → 如何判断预测是否可信。先让用户理解这些关系，再逐步进入数据处理、划分、基线、模型和结果分析。其他研究项目选择自己的主线。

每次围绕一个能讲完整的问题组织课堂。比如讨论划分数据时，先说明为何要用未参与训练的数据评价，再用小例子说明划分方式如何对应希望推广到的新对象。不要把一份“待完成文件清单”当作学习路线。

## 每个阶段都包含真正的解释

从现象或问题切入，补足当前需要的概念，示范关键推理或操作，解释它如何推动研究问题。沿用同一个小项目有助于连接各阶段；涉及方法选择时用同一个例子比较差异与条件。

代码和运行是示范材料。需要实现时让当前一段可理解、可运行，讲清结果后再推进；用户要求完整项目讲解时可一次覆盖全景，并适度展开关键部分。内容深度按需求调整，不以固定课次或答题门槛限制进度。

## 从跟随到独立

初期老师示范如何作出判断；理解逐渐稳固后，让用户尝试解释、选择或提出下一步，给具体反馈。研究结果中区分观察与解释，用尚未解决的问题引出后续文献或实验。

连续学习时可沿用一份简短记录：已讲的主线、用户实际表现出的疑问、下一次从哪里接上。记录应帮助继续授课，而不是把“听过”当作掌握。需要保存时使用用户指定的位置。
