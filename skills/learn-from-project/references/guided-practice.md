# 带着用户做，并把每一步教会

若当前实操属于更大的学习任务，先定位它在完整路线中的作用。选择一个小而完整的当前任务，说明要学的关键思想，再给能看懂的输入和目标结果。根据已有基础提供完整示范、共同补写或独立尝试。

示范时把代码放在解释附近：先讲这一步的理由，展示相关代码，再用中间值说明它做了什么。执行后解释结果与预期的关系。老师可以承担重复操作和环境排错，但讲解仍围绕用户需要理解的概念。

编写示范时按需参考 [教学代码](teaching-code.md)。若重点是理论，代码用于显出原理；若重点是编程，再展开实现方式与语言知识。

每次增加一个有意义的困难，例如从一条输入到多条、从内存例子到文件。新增函数、参数或依赖时说明它解决了刚刚遇到的什么问题；让设计从需要中长出来。

卡住时具体解释卡点，必要时直接示范答案，然后换一个小变化帮助理解。练习用于主动思考，不是获得答案的门槛。只有用户希望共同练习时才等待其实现；用户明确要求完整交付时完成工作，并讲清关键选择。

一次实操的课堂产出应包含“为什么这样做、这一段如何工作、结果说明什么”。保存了脚本或成功运行，只是其中的操作结果。

阶段完成或局部疑问解决后，接回整体目标，说明这一结果如何供下一阶段使用。需要全过程教学的组织建议时可选读 [项目教学](research-project-learning.md)。
