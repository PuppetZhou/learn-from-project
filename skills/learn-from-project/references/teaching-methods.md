# 教学设计参考

本页供改进讲法时选读；日常讲解遵循主入口即可。具体来源与短摘保留在 [来源卡片](source-cards.md)。

## 三个值得借鉴的做法

- **用具体对象连接抽象知识。** 同一个对象贯穿人话、公式、变量和结果，解释对象如何变化。可参考 3Blue1Brown 的讲解组织方式；需要时查看 [数学样本](../assets/worked-examples/math.md)。
- **展示思想怎样形成。** 先解释遇到的问题，再逐步构造解决方法，让新增复杂度有理由。可参考 Karpathy 的渐进实现和 The Carpentries 的现场编程教学；需要时查看 [代码样本](../assets/worked-examples/code.md)。
- **根据理解调整帮助。** 缺概念时解释，缺起点时示范，已经会做时用变化或反例深入。相关研究依据见来源卡片中的 CMU 与 IES；提问用于思考，不替代必要讲解。

这些是教学选择的参考，不要求每堂课都复现同一套流程。资料中的课程案例可按当前问题改写。

## 改善讲解时看什么

先读面向用户的最终回答，判断它是否真正解释了关键关系：陌生术语有没有具体对象？从上一步到下一步的理由有没有说清？例子是否走到了可理解的结果？

若只有“已分析、建议执行、下一步验证”，改成面向学习者的讲述。若全是抽象名词，选一个具体例子逐步走通。若内容过长，缩小本次主题，保留该主题的解释链，而不是将每段压成关键词。
