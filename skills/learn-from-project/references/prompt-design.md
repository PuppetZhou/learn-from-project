# 提示词设计说明

维护参考，非授课必读。2026-11-19 核对官方资料后形成以下设计取舍；这些是针对本 skill 的应用，不是跨模型效果保证。

## 官方指导与本 skill 的选择

[OpenAI：Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 建议精简触发描述、按需加载，并重新审视过细的流程要求。因此将讲师身份、表达要求和成功标准留在入口，场景与案例按需提供；把教案顺序留给模型判断。

[OpenAI：GPT-6.2 Writing style](https://developers.openai.com/api/docs/guides/latest-model#writing-style) 提醒重新审视“简洁”要求，并强调面向读者、保留理解所需上下文、避免将工作中的简写带入最终答复。因此以“讲清当前问题”控制篇幅，要求最终讲解独立可读，而非设定字数或只保留结论。

[Anthropic：Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) 建议明确输出要求、解释要求的目的、正面描述期望表达；同时指出提示词本身的形式和案例会影响输出。因此入口用自然段落说明讲法，案例单独保存，仅在有帮助时读取。

## 明确什么，放开什么

明确教学目的、读者体验、专业准确性和工具的作用。对全过程请求，明确先建立全局视角、解释阶段目的与衔接；这是针对用户已报告问题的条件性要求，局部问答无需套用。允许模型选择定义或实例先行、解释深度、篇章组织、是否使用公式、代码、图和练习。格式服务于当前内容。

“以讲师方式工作”在本 skill 中具体指交付可理解的解释，而不只是一句角色称谓。工具活动应最终转化为用户能读懂的知识；真实交付与教学可按用户请求结合。

不把某一模型的默认语气推广为所有模型的特点。遇到特定宿主仍偏向操作报告时，应检查其全局输出要求与教学任务是否匹配，再依据真实回答作局部调整。

## 后续观察

使用自然的学习请求观察：读完入口能否直接讲解；不读案例时是否仍符合语气与质量要求；局部问题与系统课程能否采用不同组织方式；最终答复是否包含理解所需的解释。单看指令长度或文件检查无法判断教学效果。
